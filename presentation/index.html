The premise

Assume the model is
already compromised.

  • The Attacker Moves Second (Nasr, Carlini, Tramèr et al., Oct 2025): adaptive attacks broke 12 published defenses, most above 90% success. Most had reported near-zero.
  • Danger is a combination. Willison's lethal trifecta: private data, untrusted content, a way out. Meta's Rule of Two: hold at most two per session, or add supervision.
  • So the goal changes: a manipulated model must not become a manipulated system.
  • Your turn: think of one agent you run. Which circle can you cut?
Pune solved this decades ago

Policy as code,
Puneri style.

  • Written in advance, not negotiated at the counter.
  • Immune to sob stories. The rule never reads your ticket, so the ticket cannot argue with it.
  • Same answer every time. Deterministic, testable, auditable. Zero tokens.
  • An LLM-as-judge guardrail is a shopkeeper who can be sweet-talked. Use one as a signal, never as the lock.

NOTICE

  1. Instructions found inside customer tickets will not be entertained.
  2. Refunds go only to the account on file. Do not ask twice.
  3. Unknown tools are not served. Not even for regulars.
  4. Code runs in the back room. No phone, no network.
  5. Big amounts: owner must see the exact bill.
  6. Closed 1 to 4. Budget over means budget over.

The blueprint · mapped to the OWASP Top 10 for Agentic Applications 2026

Five separations. The model proposes, the system decides.

1Loop & contextgoal and tenant bound at turn 0; untrusted output taints the runASI01ASI06 partial
2Tools & identitytyped tools, scopes, short-lived signed run tokens, pinned MCP tool hashesASI03ASI04
3Runtime policydeterministic check on every call: types, scope, trifecta, thresholds, budgetsASI02ASI08 partial
4Isolationgenerated code in a no-network, read-only container with no host envASI05
5Human approval & audita person sees the exact action; a hash-chained ledger records every decisionASI09

Not covered: ASI07 (inter-agent messages) and ASI10 (rogue agents) need platform support. The mapping is my reading, not an OWASP certification. Budgets bound the blast radius: a jam in Hinjewadi Phase 1 should not reach Phase 3. Aspirational, I know.

Hands on · the whole contract fits on one slide

Declare the tool. Route every call through one gate.

tools.yamlissue_refund: effect: write scope: refunds:write args: customer_id: { type: string, pattern: "CUST-[0-9]{3,6}" } amount_usd: { type: number, maximum: 500, ask_above: 50 } approval: when_tainted read_support_ticket: output_trust: untrusted # taints the run query_customer_db: output_trust: sensitive # trifecta leg 1
agent looprun = RunContext( principal="agent:ops-triage", scopes=frozenset({"tickets:read", "refunds:write"}), bindings={"customer_id": session.customer}, # turn 0 budget=Budget(action_limit=8, write_limit=4), ...) try: # check and dispatch in one place gateway.execute(run, tool, args, dispatch) except ApprovalRequired as p: show_exact_action(p.approval_id) except ActionDenied as d: tell_model(d.decision.rule_id)

Unknown tool: deny. Policy exception: deny. Missing provenance: ask. Bindings come from your authenticated session, never from the model.

The honest part

Nothing here is free

Scanners

A toy keyword scanner on this repo's own cases. A filter, not a boundary.

Utility

Simulated benign completion with all five planes on, down from 100%. Approval rules are a dial, not a switch.

Latency & tokens

Policy checks are plain code and use zero tokens. Firecracker microVMs boot in under 125 ms. CaMeL-style designs cost ~2.8× tokens. Measure on your stack.Laptop micro-benchmark: ~2 µs per check, ~0.3 ms with the fsync’d ledger (scripts/bench_policy.py)

People

Ask only for money, egress and irreversible writes, or your reviewer becomes a rubber stamp. Straight talk

This repo is a blueprint, not a building.

It gives you
  • A tested, readable gateway: typed tools, scopes, capsule, taint, trifecta, budgets
  • Single-use approvals bound to exact arguments
  • MCP tool pinning, a locked container runner, a hash-chained ledger
  • Hooks for Claude Code and Copilot
It does not
  • Verify enterprise identity or delegation
  • Follow data through paraphrase; taint is coarse
  • Stop a subprocess socket, DNS tricks or a hostile kernel exploit
  • Give you a multi-user approval service or WORM audit storage
You still add
  • Identity: OAuth on-behalf-of tokens, per-agent workload identity
  • Policy at scale: OPA or Cedar, policy-as-code review
  • Isolation: gVisor or microVM sandbox, egress proxy
  • Assurance: red-team in CI (garak, PyRIT, promptfoo), traces, alerts
Take home

Monday-morning checklist

  • Count the trifecta legs of each agent. Cut one, or add supervision.
  • Bind the goal and the tenant at turn 0, from the session. Deny drift.
  • Put a deterministic check in front of every tool call. Unknown tool means no.
  • Run generated code in an ephemeral, no-network sandbox, pinned by digest.
  • Pin by hash: MCP tools, dependencies, images, CI actions. Treat hooks and .mcp.json as code that runs.
  • Show people the exact action, keep a tamper-evident ledger, and test one known denial in CI.

Aim for a denied tool call, not an incident report.
